# 04. 物流・オペレーション設計

物流は越境ECの原価の2番目に大きい要素であり、**顧客体験の9割を決めます**。ここの設計を誤ると、商材が良くても評価が下がり、モールでの露出が落ちて事業が止まります。

---

## 1. 配送手段の比較（日本 → 米国）

| 手段 | 目安コスト（1kg） | 日数 | 追跡 | 関税処理 | 補償 | 使いどころ |
| --- | --- | --- | --- | --- | --- | --- |
| **国際eパケット / 小形包装物** | 安い | 2〜4週間 | 弱い | DDU（受取人負担） | 少額 | **非推奨**。de minimis廃止後は受取人が関税請求を受けてトラブル化する |
| **EMS** | 中 | 1〜2週間 | あり | DDU | 一定額まで | 低〜中単価。ただし関税処理の問題は残る |
| **クーリエ（DHL / FedEx / UPS）** | 高（法人契約で30〜60%割引） | **3〜6日** | 強い | **DDP対応可** | 高い | **✅ 推奨。Phase 0の標準** |
| **フォワーダー混載 → 現地3PL** | 大量なら最安 | 2〜4週間（初回輸送） | — | 一括通関 | 貨物保険 | **✅ Phase 1で在庫を先出しする際の標準** |
| **Amazon FBA（現地在庫）** | 輸送費＋FBA手数料 | **顧客へは1〜2日** | 強い | 一括通関済み | Amazon規定 | **✅ Phase 1。転換率が跳ね上がる** |

### 推奨構成

- **Phase 0（直送）**: クーリエ法人契約 + DDP。速くて追跡が確実で、関税トラブルが起きない
- **Phase 1（現地在庫）**: 勝ちSKUをフォワーダー経由でまとめて輸出 → FBA または現地3PL

**郵便系（eパケット・EMS）を主軸にしないでください。** 2026年のde minimis廃止により、受取人が着荷時に関税とブローカー手数料を請求される事態が常態化しました。受取拒否・返送・低評価・返金の連鎖が起き、モールのアカウント健全性指標を直撃します。**送料を数百円ケチって評価を落とすのは、越境ECで最も高くつく間違いです。**

---

## 2. DDP を標準にする

| 条件 | 誰が関税を払うか | 顧客体験 |
| --- | --- | --- |
| **DDU / DAP** | 受取人が着荷時に支払う | ✕ 「知らない請求が来た」→ 受取拒否・低評価・返金 |
| **DDP** | **販売者が事前に支払う（価格に織り込む）** | ◎ 表示価格ですべて完結する |

**必ずDDPにしてください。** 商品ページには "Import duties and taxes included — no additional charges on delivery" と明記します。これは転換率に対して、写真や説明文よりも大きく効きます。

**価格設計**: 関税率は商材のHTSコードによって0〜20%程度と幅があります。カテゴリごとに実効税率を調べ、**販売価格に「関税率 + 通関手数料の按分」を上乗せ**します。分からないうちは保守的に見積もり（15%程度）、実績が出たら精緻化します。

## 3. 出荷オペレーション（SOP）

一点物商材の場合、1SKUあたりの処理工数が事業のスループットを決めます。**最初から計測してください。**

### 標準フロー

```
① 仕入れ  →  ② 検品・撮影  →  ③ 出品  →  ④ 受注  →  ⑤ 梱包  →  ⑥ 発送  →  ⑦ 証憑保存  →  ⑧ アフター
```

| 工程 | 目標時間 | 内容とポイント |
| --- | --- | --- |
| ② 検品・撮影 | 15分/点 | 撮影ブースを固定（背景・照明・カメラ位置）。**傷や欠点は必ず写す**。後のクレーム対応時間が激減する |
| ③ 出品 | 10分/点 | タイトルのテンプレート化。英語はテンプレ + 固有情報のみ手入力 |
| ⑤ 梱包 | 8分/件 | 資材を3サイズに標準化。緩衝材は現地の輸送環境（乱暴）を前提に厚めに |
| ⑥ 発送 | 3分/件 | クーリエの管理画面でラベル発行。インボイス3部を同梱 |
| ⑦ 証憑保存 | 2分/件 | **注文IDでファイル名を統一**。台帳に1行追加。→ 消費税還付の生命線 |

**合計 約38分/件。** 月100件なら63時間。ここを半分にできれば、同じ人員で倍売れます。

### 撮影の標準化が最も効く

- 背景紙・LEDライト・三脚を固定設置して、置くだけで同じ絵が撮れる状態を作る
- 撮影カット順をリスト化（正面 / 背面 / 側面 / 型番 / 傷1 / 傷2 / 付属品一式）
- ファイル名を `{SKU}_{連番}.jpg` に自動リネームする

## 4. 商業インボイス（Commercial Invoice）

通関に必須の書類です。**記載ミスは通関保留・遅延・課税額の誤りに直結**します。

必須記載事項:
- 発送元（社名・住所・電話・EORI/税務番号があれば）
- 発送先（氏名・住所・電話・メール）
- 品名（**具体的に。"Gift" や "Sample" は使わない。虚偽記載は密輸に問われうる**）
- **HSコード（6桁）** — 相手国は10桁に展開する
- 数量・単価・合計金額・通貨
- 原産国（Country of Origin）
- Incoterms（**DDP**）
- 署名

**やってはいけないこと。**
- 「関税を安くするため」に価格を過少申告する — 関税ほ脱。事業ごと終わります
- 商用品を "Gift" と記載する — 同上
- 品名を "Goods" のような曖昧な語にする — 通関保留の原因

## 5. 返品・カスタマーサポート

| 論点 | 推奨対応 |
| --- | --- |
| 返品先住所 | Phase 1以降は**米国内の返送先を持つ**（3PLの返品受付サービス）。国際返送は顧客負担が重く、返品率より不満率が上がる |
| 少額品の返品 | 返送コスト > 商品価値 の場合は**返送不要で返金**する方が総コストが安い。ポリシーとして基準額を決めておく |
| 返答速度 | **24時間以内**。eBayもAmazonも応答速度を評価指標にしている |
| 言語 | 定型文を英語でテンプレ化（発送通知、遅延の謝罪、返品受付、部分返金提案）。AI翻訳は下書きに使い、送信前に必ず読む |
| 紛失・破損 | クーリエの補償請求フローを事前に確認。まず顧客に再送か返金を即決し、補償請求は自社で追う（顧客を待たせない） |

**サポートの原則: 顧客を「調査の完了」まで待たせない。** 越境ECは配送に不確実性があるため、問題が起きるのは前提です。差がつくのは**問題が起きた後の速度**です。

## 6. 在庫管理

| Phase | 在庫の持ち方 | 管理方法 |
| --- | --- | --- |
| Phase 0 | 買い切り、自宅/小規模倉庫、日本国内のみ | スプレッドシートで十分（SKU・仕入日・原価・保管場所・出品URL・販売日・売価） |
| Phase 1 | 日本 + 米国（FBA/3PL）の2拠点 | 在庫管理ツール導入。**拠点をまたぐと手作業では破綻する** |
| Phase 2 | 複数拠点 + 複数チャネル | OMS/WMS。チャネル間の在庫連携が必須 |

**在庫の健全性指標。**
- **在庫回転率 6回/年以上**（＝平均在庫日数60日以下）
- **90日以上の滞留在庫が総在庫額の20%を超えたら、値下げして現金化する**

越境ECで倒れる最大の原因は「売れない在庫に現金が変わったまま戻らない」ことです。**利益率より現金化速度を優先する局面がある**ことを、経営判断として最初に決めておいてください。

## 7. 使うツール（初期構成）

| 領域 | ツール | 月額目安 |
| --- | --- | --- |
| 会計 | freee / マネーフォワード（法人） | 3,000〜5,000円 |
| 外貨受取 | Wise Business / Payoneer | 従量 |
| 在庫・受注 | スプレッドシート → Phase 1でネクストエンジン等 | 0 → 10,000円〜 |
| 出品支援 | eBay Seller Hub、Amazon Seller Central（標準機能） | 0 |
| リサーチ | Terapeak（eBay標準）、Keepa（Amazon価格履歴） | 0〜3,000円 |
| 証憑保管 | Google Drive（注文IDでフォルダ分け） | 既存 |
| 為替・関税 | 通関業者の見積、HSコード検索（税関 Web Tariff） | 0 |

**最初からツールを積み上げないでください。** Phase 0で必要なのは会計ソフトと外貨受取だけです。売上が立つ前にツール代で月3万円使うのは典型的な失敗です。
